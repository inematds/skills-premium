🔄 O prompt de reverse meta prompting

O reverse meta prompting é uma das técnicas mais poderosas para evoluir skills porque inverte o fluxo natural de criação. Ao invés de você pensar no que a skill precisa, você pede para o próprio agente que vai executá-la analisar o que está faltando. O agente tem uma perspectiva única: ele sabe exatamente onde as instruções são ambíguas, onde faltam exemplos, onde o trigger poderia ser melhor e onde o output poderia ser mais útil. Essa perspectiva é literalmente impossível de obter de outra forma — só o executor sabe o que precisa para executar melhor. O prompt completo abaixo captura essa perspectiva de forma estruturada e produz melhorias concretas e implementáveis em uma única sessão.

🎯 Conceito Principal: Inversão de perspectiva

O reverse meta prompting funciona porque quebra um viés fundamental: o criador de uma skill está tão familiarizado com ela que não consegue ver suas falhas óbvias. O executor as vê imediatamente. O prompt abaixo força essa perspectiva de forma sistemática.

💥 Prompt Completo: Reverse Meta Prompting

Você vai analisar a skill abaixo como se fosse executá-la pela primeira
vez, sem nenhum contexto adicional além do que está escrito.

[COLE O CONTEÚDO COMPLETO DA SKILL AQUI]

Analise a skill acima respondendo cada ponto:

## 1. Análise de Trigger
- O trigger na description é claro e inequívoco?
- Há situações em que você ficaria em dúvida se deve acionar ou não?
- O trigger pode ser confundido com outra skill que você conhece?
- Proposta de melhoria do trigger (se necessário):

## 2. Análise de Instruções
- As instruções são completas para o fluxo principal?
- Há alguma instrução que pode ser interpretada de duas formas?
- Falta alguma instrução para os casos mais comuns de variação?
- Liste os 3 gaps mais críticos nas instruções:

## 3. Análise de Output
- O formato de saída está claro?
- O nível de detalhe solicitado é adequado ao propósito?
- Há algum caso em que o output seria inadequado ou insuficiente?
- Como o output poderia ser mais útil para quem vai usar?

## 4. Análise de Contexto
- A skill assume alguma informação que pode não estar disponível?
- Há dependências de outras skills ou ferramentas que deveriam ser explícitas?
- O que o usuário precisa saber antes de acionar essa skill?

## 5. Proposta de Reescrita
Com base na análise acima, reescreva a skill completa incorporando
todas as melhorias identificadas. A nova versão deve:
- Corrigir todos os gaps críticos identificados
- Manter o propósito e o comportamento essencial da skill original
- Ser mais clara e mais completa do que a versão atual

## 6. Resumo das Mudanças
Liste em bullet points o que mudou e por quê.

💡 Dica Prática

Use este prompt logo após criar uma skill nova, antes de publicá-la. Você vai encontrar entre 3 e 7 melhorias em qualquer skill, independente de quão bem você acha que ela está. A primeira versão nunca é a melhor. O reverse meta prompting garante que a versão publicada já incorpora a perspectiva do executor.

🤖 O prompt de auditoria com claude-code-guide

O agente claude-code-guide tem acesso ao sistema de arquivos e a contexto técnico profundo sobre como skills funcionam na prática dentro do Claude Code. Isso o torna excepcionalmente eficaz para auditorias que vão além da análise textual — ele pode verificar se os triggers fazem sentido no contexto real de uso, se há conflitos com outras skills no sistema e se as instruções são tecnicamente viáveis. O prompt abaixo ativa esse agente de forma estruturada, passando o contexto necessário e solicitando a análise nos pontos de maior valor. O resultado é uma auditoria técnica que combina perspectiva de executor com conhecimento especializado sobre o ambiente de execução.

💥 Prompt Completo: Auditoria com Agente Especializado

Use o agente claude-code-guide para auditar a skill abaixo.

[COLE O CONTEÚDO COMPLETO DA SKILL AQUI]

Instruções para o agente:

Você é um especialista em skills para Claude Code. Sua missão é auditar
a skill acima com profundidade técnica e imparcialidade total.

## Fase 1 — Análise Técnica
Verifique:
1. O trigger é compatível com como o Claude Code reconhece acionamentos?
2. As instruções são tecnicamente executáveis dentro das capacidades do modelo?
3. Há dependências de ferramentas ou contextos que podem não estar disponíveis?
4. O formato de output é consistente com as capacidades de formatação disponíveis?

## Fase 2 — Análise de Consistência
Verifique:
1. As instruções internas são consistentes entre si?
2. Há contradições entre o que a description promete e o que as instruções entregam?
3. O escopo declarado (o que a skill faz) é igual ao escopo real (o que as instruções produzem)?

## Fase 3 — Análise de Cobertura
Verifique:
1. A skill cobre os casos de uso mais comuns do seu propósito declarado?
2. Há casos óbvios não cobertos que deveriam estar?
3. Há casos cobertos que vão além do propósito declarado (scope creep)?

## Fase 4 — Classificação de Findings
Para cada problema encontrado, classifique:
- CRÍTICO: Impede uso correto da skill
- IMPORTANTE: Degrada significativamente a qualidade do output
- MENOR: Melhoria desejável mas não urgente

## Fase 5 — Relatório Final
Produza um relatório estruturado com:
- Resumo executivo (3 frases)
- Lista de findings por severidade
- Top 3 melhorias recomendadas com justificativa
- Skill revisada incorporando as correções críticas e importantes

💡 Dica Prática

Este prompt é mais pesado do que o reverse meta prompting — use-o para skills críticas que você usa diariamente, não para toda skill da biblioteca. Reserve para as 20% de skills que geram 80% do valor, e que merecem o investimento de uma auditoria aprofundada.

🏗️ O prompt de crítica estrutural

Feedback positivo não melhora skills. O que melhora é feedback adversarial — alguém (ou algo) que ativamente tenta encontrar os pontos fracos. O prompt de crítica estrutural configura o modelo para assumir explicitamente uma postura de crítico implacável, sem suavizar os problemas encontrados. Ele busca as falhas que você nunca considerou: casos extremos que a skill não consegue tratar, ambiguidades que levam a outputs completamente errados em certas situações, e suposições não declaradas que funcionam bem no seu contexto mas falham no de qualquer outra pessoa. A ideia é simples mas poderosa: você não sabe o que não sabe sobre sua própria skill, e só um exercício adversarial consegue revelar isso.

💥 Prompt Completo: Crítica Estrutural

Você é um crítico adversarial especializado em encontrar falhas em skills
para assistentes de IA. Sua missão é demolir a skill abaixo — encontrar
todas as suas fraquezas, inconsistências, lacunas e casos de falha.

NÃO seja gentil. NÃO elogie o que está bom. Foque EXCLUSIVAMENTE nos
problemas. Seja implacável.

[COLE O CONTEÚDO COMPLETO DA SKILL AQUI]

## Análise Adversarial

### 1. Falhas de Trigger
- Em que situações o trigger seria acionado erroneamente?
- Em que situações deveria ser acionado mas não seria?
- Há triggers de outras skills que podem colidir com este?

### 2. Casos de Falha Críticos
Descreva 3-5 cenários em que esta skill produziria output errado,
incompleto ou prejudicial. Para cada cenário:
- Situação: O que o usuário está tentando fazer
- Expectativa: O que deveria acontecer
- Falha: O que realmente aconteceria com as instruções atuais
- Impacto: Por que isso é um problema real

### 3. Suposições Ocultas
Liste todas as suposições não declaradas que a skill faz:
- Sobre o nível técnico do usuário
- Sobre o contexto de trabalho
- Sobre as ferramentas disponíveis
- Sobre o que é "óbvio" mas não está escrito

### 4. Ambiguidades Fatais
Liste todas as instruções que podem ser interpretadas de duas formas
significativamente diferentes. Para cada uma:
- A instrução ambígua
- Interpretação A (e o que ela produziria)
- Interpretação B (e o que ela produziria)
- Por que a diferença importa

### 5. Veredicto Final
Com base na análise: esta skill é utilizável no estado atual?
- Sim, com os ajustes X, Y, Z
- Não, precisa de reescrita significativa por causa de...

Forneça também uma versão melhorada que endereça as falhas críticas.

💡 Dica Prática

Quando receber o relatório de crítica estrutural, resista ao impulso defensivo. Cada falha identificada é um presente. Priorize os casos de falha críticos — cenários em que a skill produziria output ativamente prejudicial — antes de qualquer outra melhoria.

🧩 O prompt de consolidação

Quando você suspeita que duas ou mais skills estão fazendo coisas similares, o prompt de consolidação é a forma mais eficiente de confirmar a suspeita e agir sobre ela. Ele analisa as skills em conjunto, mapeia com precisão o que se sobrepõe e o que é exclusivo de cada uma, e produz uma proposta de consolidação com justificativa detalhada para cada decisão. O processo inclui uma matriz de sobreposição que torna visível o que antes estava implícito, e uma skill consolidada que incorpora o melhor de cada versão original. O diferencial em relação a uma consolidação manual é a sistematicidade: nenhum caso de uso é esquecido e nenhuma decisão é tomada por intuição.

💥 Prompt Completo: Consolidação de Skills

Analise as skills abaixo para identificar sobreposições e propor
uma consolidação que preserve toda a funcionalidade existente.

=== SKILL A ===
[COLE O CONTEÚDO COMPLETO DA SKILL A AQUI]

=== SKILL B ===
[COLE O CONTEÚDO COMPLETO DA SKILL B AQUI]

=== SKILL C (se houver) ===
[COLE O CONTEÚDO COMPLETO DA SKILL C AQUI]

## Fase 1 — Mapeamento Individual
Para cada skill, extraia:
1. Propósito central (1 frase máximo)
2. Triggers (todas as condições de acionamento)
3. Comportamentos exclusivos (o que só ela faz)
4. Comportamentos compartilhados (o que outras também fazem)

## Fase 2 — Matriz de Sobreposição
Crie uma tabela com todos os comportamentos identificados:
| Comportamento | Skill A | Skill B | Skill C | Decisão |
|---|---|---|---|---|
Liste cada comportamento e marque quais skills o possuem.
Para comportamentos compartilhados, indique qual versão é melhor.

## Fase 3 — Decisões de Consolidação
Para cada sobreposição identificada:
- O que manter da Skill A e por quê
- O que manter da Skill B (ou C) e por quê
- Como os comportamentos conflitantes serão resolvidos

## Fase 4 — Skill Consolidada
Produza a skill consolidada completa, incluindo:
- Nome e description unificados
- Triggers que cobrem todos os casos originais
- Instruções integradas sem perda de funcionalidade
- Comentário interno documentando o que foi consolidado

## Fase 5 — Plano de Teste
Liste os casos de teste necessários para validar que a skill
consolidada cobre 100% dos casos de uso originais.

## Fase 6 — Recomendação Final
Deve consolidar? Justificativa em 2-3 frases.
Se sim: quando e como arquivar as skills originais.
Se não: por que manter separado é melhor neste caso.

💡 Dica Prática

Execute o plano de teste antes de arquivar as skills originais. A consolidação pode parecer perfeita no papel e falhar em casos reais. Teste primeiro, archive depois — nunca o contrário.

⛓️ Combinando prompts em sequência

Cada prompt canhão tem um ângulo específico de análise: o reverse meta prompting enxerga pelo olho do executor, a crítica estrutural busca falhas adversarialmente, e o prompt de auditoria técnica verifica viabilidade de execução. Nenhum deles sozinho consegue ver tudo — mas combinados em sequência, cobrem virtualmente todos os ângulos possíveis de melhoria. O encadeamento ideal passa o output de cada prompt como input do próximo, criando um loop de refinamento progressivo que converge para uma skill muito mais robusta. O segredo está na ordem: começar com análise ampla (reverse meta), afunilar para problemas específicos (crítica estrutural), e finalizar com validação técnica (auditoria).

⛓️ Sequência Recomendada para Melhoria Profunda

1

Reverse Meta Prompting

Perspectiva do executor — o que está faltando para executar bem

Output: skill melhorada (V2) + lista de mudanças

2

Crítica Estrutural (aplicar ao V2)

Postura adversarial — encontrar o que ainda está fraco

Output: lista de falhas residuais + skill melhorada (V3)

3

Auditoria Técnica (aplicar ao V3)

Validação de viabilidade técnica e cobertura

Output: versão final aprovada (V4) ou lista de correções

4

Revisão Humana (você)

Aprovação final antes de publicar

Verificar se as mudanças fazem sentido no seu contexto específico

💡 Dica Prática

Para skills menos críticas, use apenas o passo 1 (reverse meta prompting). Para skills de alta frequência de uso, execute os 3 passos de agente antes da revisão humana. O investimento de tempo vale proporcionalmente ao valor que a skill gera.

🧭 Quando usar cada um

Ter os prompts canhão disponíveis não é suficiente — você precisa saber qual usar em cada situação para não desperdiçar tempo e tokens. O diagnóstico correto do problema é o que determina a escolha certa. Uma skill que nunca foi revisada precisa de reverse meta prompting. Uma skill que está falhando em casos específicos precisa de crítica estrutural. Uma skill que parece boa mas tem comportamentos inconsistentes precisa de auditoria técnica. E um par de skills sobrepostas precisa do prompt de consolidação. O framework a seguir transforma esse processo de seleção em uma decisão sistemática baseada em sintomas observáveis em vez de intuição.

🧭 Guia de Decisão: Qual prompt usar?

Sintoma: "Acabei de criar uma skill nova"

→ Usar: Reverse Meta Prompting

Toda skill nova se beneficia da perspectiva do executor antes de ser publicada.

Sintoma: "A skill funciona em geral mas falha em algumas situações"

→ Usar: Crítica Estrutural

Falhas em casos específicos indicam fraquezas estruturais que a crítica adversarial vai encontrar.

Sintoma: "A skill é crítica e quero garantia máxima de qualidade"

→ Usar: Sequência completa (3 prompts em ordem)

Para skills de alto impacto, o investimento em cobertura total vale o esforço.

Sintoma: "Tenho duas skills que parecem fazer coisas similares"

→ Usar: Prompt de Consolidação

A sobreposição precisa ser quantificada antes de qualquer decisão de fusão ou manutenção separada.

Sintoma: "Uma skill está se comportando de forma inconsistente"

→ Usar: Auditoria com claude-code-guide

Inconsistências são sintomas de problemas técnicos que requerem análise especializada.

✓ O que FAZER

  • ✓Diagnosticar antes de escolher o prompt
  • ✓Usar o prompt mais simples que resolve o problema
  • ✓Escalar para prompts mais pesados se o simples não resolver
  • ✓Aplicar revisão humana sempre antes de publicar

✗ O que NÃO fazer

  • ✗Usar a sequência completa para toda skill nova
  • ✗Escolher o prompt por familiaridade, não por necessidade
  • ✗Publicar sem revisão humana após qualquer prompt
  • ✗Aplicar o prompt de consolidação sem ter testado individualmente
